# Buildwise Media homepage design commission

## Assignment

Create one original, high-fidelity homepage direction for Buildwise Media.

This is a blind, private design study. Do not view, inspect, imitate, or reuse:

- buildwisemedia.com
- any existing Buildwise homepage source
- any prior Buildwise taste-lab or comparison design
- any other candidate in this study

Start from the business and brand facts below. The design must be your own point of view: palette, typography, composition, section transitions, visual language, and interaction choices.

## What Buildwise is

Buildwise Media works with established service businesses to become AI-native. It builds and improves custom AI systems across the business. The relationship starts with one important operating problem, but it is meant to continue: learn from real work, improve what works, and build the next useful system.

The 90-day Pilot is the way into the relationship. It is not the whole relationship, and the page must not make Buildwise sound like a one-project shop, a generic automation vendor, or a marketing agency.

The audience is an experienced owner or executive. They are smart and busy. The page should feel clear, confident, useful, and easy to read—not technical for its own sake.

## Logo lock

Use the supplied `brand/mark.svg` unchanged. Do not redraw, recolor, distort, crop, animate, or reinterpret it. Pair it with the text `Buildwise Media` in the navigation. The logo mark is the only visual asset inherited from the current brand.

## Creative freedom

You own the new design direction:

- Choose a distinct color system. You are not required to use the current website palette. Avoid an all-monochrome page.
- Choose a new display and body type direction. Use system/local fallbacks so the prototype has no external dependency.
- Create strong section differentiation and a clear visual path down the page.
- Create one functional visual system or diagram that explains the long-term Buildwise relationship. It must aid understanding, not decorate empty space.
- Use restrained, optional motion only if the design is complete without it.
- Make the experience work at 1440px and 390px.

## UX and accessibility floors

- Body copy must be at least 18px on desktop and 17px on mobile.
- Maintain strong contrast, visible focus states, and semantic structure.
- No horizontal overflow at 390px.
- The eye should know where to look next in every section.
- No dense card grids, tiny labels, generic AI circuit imagery, floating decoration, stock photography, fake dashboards, invented testimonials, or unverified metrics.
- Do not make the Pilot look like the end of the relationship.

## Required outputs

Create exactly these files in your assigned repository:

1. `candidate.html` — a self-contained responsive prototype using only local `brand/mark.svg`, inline CSS, and inline JavaScript if needed.
2. `design-rationale.md` — concise notes covering the concept, palette, typography, composition, visual-story logic, mobile behavior, and what makes this direction unlike a standard AI-company site.
3. `author-receipt.json` — valid JSON with `author_model`, `concept_name`, `created_at`, and `source_files`.

Do not include your model name anywhere inside `candidate.html`; the comparison must remain blind until reveal.

## Image-function annotations

Place a nearby annotation above every non-icon SVG or image:

- `@r020:F2` for explanatory/proof diagrams
